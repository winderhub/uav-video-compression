# 航拍视频压缩桌面应用

桌面应用继承原位 Bash 脚本的核心行为，同时保留原有脚本，不替换服务器工作流。

## 固定压缩参数

~~~text
编码器：       libx264（CPU）
preset：       fast
质量：         CRF 18
像素格式：     yuv420p
容器优化：     +faststart
视频流：       只保留第一路视频
音频：         删除
DJI 私有流：   删除
分辨率/帧率：  不主动改变
~~~

桌面版的视频并发固定为 1。安静、均衡和全速档位只改变单个编码器的线程数，不改变上述质量参数：

| 档位 | 线程数（按逻辑处理器估算） |
|---|---:|
| 安静 | 25% |
| 均衡 | 50%，默认 |
| 全速 | 75% |

例如 16 个逻辑处理器对应 4、8、12 个编码线程。

扫描后界面显示视频数量、总输入大小、按历史压缩比例估算的输出大小、当前可用空间和最低建议空间。由于不同电脑性能差异很大，首次启动不凭 CPU 型号猜测耗时；完成第一个视频后，软件按本机实测速度动态估算剩余时间。

## 文件安全流程

源位置空间充足时：

~~~text
源视频
  -> 同目录 *.compress_tmp.MP4
  -> 刷新文件缓存
  -> FFprobe 校验包数
  -> 同存储卷原子替换
  -> 恢复原修改时间
~~~

源位置空间不足时，用户必须选择另一个存储卷上的备用临时目录：

~~~text
在备用目录生成并校验压缩文件
  -> 确认写回容量
  -> 删除源视频（已验证压缩副本仍在备用目录）
  -> 复制为源位置 *.restore_partial.MP4
  -> 再次校验复制结果
  -> 重命名为原文件名
  -> 删除备用副本
~~~

跨盘写回中断时，备用目录中的已验证压缩文件不会删除。恢复源路径后再次启动任务即可重新写回。

空间检查使用保守公式：

~~~text
最低建议剩余空间 = 最大原视频大小 × 1.25 + 1 GiB
~~~

## 文件占用与路径异常

- 开始处理单个视频前检查文件是否被占用。
- 压缩前发现占用时不生成临时文件，标记后继续检查其他视频。
- 压缩后替换时才发现占用，会保留当前唯一一个已验证临时文件并暂停整批任务。
- 源路径或临时目录发生 I/O 错误时暂停整批任务，不继续制造失败文件。
- 编码或验证失败的临时视频默认删除，只保留日志。

## SQLite 续跑

选择视频目录后会创建隐藏状态目录：

~~~text
所选视频目录/
└── .video-compressor/
    ├── state.sqlite3
    ├── logs/
    └── reports/
~~~

数据库记录每个文件的大小、原修改时间、码率、包数、临时路径和处理状态。电脑重启后：

- 已完成文件直接跳过。
- 压缩中断的当前文件从头重做。
- 已校验但尚未替换的文件优先恢复替换，不重新编码。
- 跨盘写回中断时从保留的本地压缩副本恢复。

“清理记录”会删除数据库、日志和报告。清理后软件无法再识别已经完成的视频，重新扫描可能造成二次有损压缩，因此有等待恢复的文件时禁止清理。

## 源码运行

要求 Python 3.8+、Tkinter、FFmpeg 和 FFprobe：

~~~bash
python3 desktop_app/main.py
~~~

无界面诊断：

~~~bash
python3 desktop_app/main.py --diagnose
~~~

可用环境变量指定 FFmpeg：

~~~text
VIDEO_COMPRESSOR_FFMPEG
VIDEO_COMPRESSOR_FFPROBE
~~~

## 平台产物

- Windows 10/11 x64 主安装包。
- Windows 7 SP1 x64 兼容包，使用 Python 3.8 单独构建和验证。
- macOS Intel (`x86_64`) 应用。
- macOS Apple Silicon (`arm64`) 应用。

PyInstaller 不能在 Linux 上直接生成 Windows/macOS 成品，必须在各目标系统上分别执行 [`packaging/README.md`](../packaging/README.md) 中的构建流程。
