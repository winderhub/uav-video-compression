# 航拍视频压缩桌面应用使用指南

## 概览

桌面应用面向 Windows 和 macOS 用户。选择视频目录后，应用会逐个压缩 MP4/MOV 文件，验证压缩结果并安全替换原文件。FFmpeg 和 FFprobe 已包含在正式安装包中。

桌面版只负责压缩，不包含百度网盘上传。

## 下载与安装

打开项目的 [Releases 页面](https://github.com/winderhub/uav-video-compression/releases/latest)，根据电脑选择文件：

| 系统 | 文件名 |
|---|---|
| Windows 10/11 64 位 | `AerialVideoCompressor-<版本>-Windows-x64-Setup.exe` |
| Intel Mac | `AerialVideoCompressor-<版本>-macOS-x86_64.dmg` |
| Apple Silicon Mac | `AerialVideoCompressor-<版本>-macOS-arm64.dmg` |

### Windows

1. 双击 `Setup.exe`。
2. 按安装向导完成安装。
3. 从开始菜单或桌面快捷方式启动应用。

当前安装包没有商业代码签名证书。Windows SmartScreen 可能显示提醒，内部试用时需要点击“更多信息”，再选择“仍要运行”。

### macOS

1. 双击对应芯片类型的 DMG。
2. 把应用拖入 `Applications` 文件夹。
3. 从 Finder 打开应用。

当前应用只有 ad-hoc 签名，没有 Apple Developer ID 公证。首次启动时，可能需要在 Finder 中右键应用并选择“打开”，或者在“系统设置 → 隐私与安全性”中允许打开。

## 第一次压缩

1. 确认原视频已有备份，或者可以从存储卡重新获取。
2. 启动应用并选择包含视频的目录。
3. 等待扫描完成，核对视频数量、总输入大小和空间提示。
4. 选择 CPU 档位。第一次使用建议保持默认的“均衡”。
5. 开始压缩，先完成少量视频。
6. 抽样检查画面、分辨率、帧率和下游使用效果，再处理整批数据。

应用的视频并发固定为 1。CPU 档位只改变单个编码器的线程数，不改变画质参数：

| 档位 | 编码线程数 |
|---|---:|
| 安静 | 逻辑处理器的 25% |
| 均衡 | 逻辑处理器的 50%，默认 |
| 全速 | 逻辑处理器的 75% |

例如，16 个逻辑处理器对应 4、8、12 个编码线程。

## 固定压缩参数

```text
编码器：       libx264（CPU）
preset：       fast
质量：         CRF 18
像素格式：     yuv420p
容器优化：     +faststart
视频流：       只保留第一路视频
音频：         删除
DJI 私有流：   删除
分辨率/帧率：  不主动改变
```

CRF 18 是高质量有损压缩，不是无损压缩。不要在清除状态记录后对已经压缩的视频再次处理，否则会产生二次有损压缩。

## 文件安全流程

### 源位置空间充足

```text
源视频
  → 同目录生成 *.compress_tmp.MP4
  → 刷新文件缓存
  → FFprobe 校验视频包数
  → 同存储卷原子替换
  → 恢复原修改时间
```

编码或验证失败时，原文件不会被替换。

### 源位置空间不足

应用会要求选择另一个存储卷上的备用临时目录：

```text
在备用目录生成并校验压缩文件
  → 确认源位置有写回空间
  → 删除源视频，已验证副本仍在备用目录
  → 复制为源位置 *.restore_partial.MP4
  → 再次校验复制结果
  → 重命名为原文件名
  → 删除备用副本
```

跨盘写回中断时，备用目录中的已验证压缩文件会保留。恢复源路径后重新启动任务，应用会优先尝试写回，不会重新编码。

最低建议空间采用保守公式：

```text
最大原视频大小 × 1.25 + 1 GiB
```

## 中断续跑与状态目录

选择视频目录后，应用会创建隐藏状态目录：

```text
所选视频目录/
└── .video-compressor/
    ├── state.sqlite3
    ├── logs/
    └── reports/
```

数据库记录文件大小、原修改时间、码率、视频包数、临时路径和处理状态。重新启动后：

- 已完成文件直接跳过。
- 编码中断的当前文件从头重做。
- 已验证但尚未替换的文件优先恢复替换。
- 跨盘写回中断时，从保留的压缩副本恢复。

“清理记录”会删除数据库、日志和报告。清理后，应用无法判断哪些视频已经完成。有等待恢复的文件时禁止清理记录。

## 文件占用和异常处理

- 压缩前发现文件被其他程序占用时，不生成临时文件，并继续检查其他视频。
- 替换阶段发现文件被占用时，保留唯一一个已验证临时文件并暂停整批任务。
- 源路径或临时目录发生 I/O 错误时，暂停整批任务。
- 编码或验证失败的临时视频默认删除，只保留日志。
- 不要在播放器、剪辑软件或同步软件占用视频时启动替换。

## 估算时间

不同电脑和视频编码差异很大，应用不会仅凭 CPU 型号猜测首次耗时。完成第一个视频后，应用会根据本机实测速度动态估算剩余时间。

## 常见问题

### 安装后出现系统安全提醒

当前内部试用安装包没有商业代码签名或 Apple 公证。请确认文件来自本仓库 Releases，并按“下载与安装”中的步骤打开。正式对外分发前应配置 Windows 代码签名和 Apple 公证。

### 找不到 FFmpeg

正式安装包应内置 FFmpeg 和 FFprobe。若应用提示缺失，请重新下载安装包，不要从源码 ZIP 中直接启动 `main.py`。

### 文件一直显示被占用

关闭播放器、剪辑软件、资源管理器预览窗格和可能正在同步该文件的程序，然后重新扫描。

### 空间不足

释放源存储空间，或者选择位于另一个存储卷且空间充足的备用临时目录。同一存储卷上的另一个文件夹不能解决空间不足问题。

### 如何查看失败原因

打开所选视频目录下的 `.video-compressor/logs/` 和 `.video-compressor/reports/`。在确认没有待恢复任务前，不要删除整个状态目录。

## 发布前人工验收

维护者在把安装包交给采集人员前，至少应确认：

1. 应用能启动并识别内置 FFmpeg。
2. 能扫描真实 DJI MP4。
3. 完成一个视频后，分辨率、帧率和画面符合预期。
4. 中途关闭再启动可以继续。
5. 源位置空间不足时能选择电脑磁盘作为备用目录。
6. 替换完成后文件名不变，没有残留临时视频。

构建方法见[安装包构建与发布](building-installers.md)。
